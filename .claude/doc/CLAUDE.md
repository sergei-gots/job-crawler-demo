# CLAUDE.md - Обучающая документация (.claude/doc/)

## Назначение каталога

`.claude/doc/` - это **обучающие материалы**, а не проектная документация. Их цель -
разбор технологического стеке проекта, а не описать API/архитектуру для других разработчиков.

Это отдельная роль от `README.md`/`ARCHITECTURE.md`/`.claude/features/`:

| Каталог/файл                   | Роль                                                                   | Аудитория            |
| ------------------------------ | ---------------------------------------------------------------------- | -------------------- |
| `README.md`, `ARCHITECTURE.md` | Формальное описание проекта                                            | Любой разработчик    |
| `.claude/features/`            | Решения и обоснования по конкретным инкрементам ("почему сделали так") | Разработчики проекта |
| `.claude/doc/`                 | Обучающий разбор технологий стека - "как это работает и зачем"         | Любой разработчик    |

## Язык: русский - осознанное исключение

Корневой `CLAUDE.md` требует английский везде, кроме `.notes/` (git-ignored). \*\*`.claude/doc/`

- намеренное исключение из этого правила\*\*: файлы на русском и при этом закоммичены в git (не
  в `.gitignore`), потому что это личные обучающие материалы Сергея, а не user-facing документация
  или код. Исключение зафиксировано и в корневом `CLAUDE.md` - не воспринимать русский текст в этом
  каталоге как нарушение основного правила.

## Структура

- **`.claude/doc/TECH_STACK_OVERVIEW.md`** - главный файл, макро-обзор всего стека. Таблицы
  "технология → зачем нужна" по backend/frontend/инфраструктуре плюс общий вывод про идею стека
  для доклада.
- **`.claude/doc/modules/<MODULE_NAME>.md`** - файлы для глубокого разбора одной конкретной
  технологии/модуля, на которую в `TECH_STACK_OVERVIEW.md` можно (и нужно) сослаться ссылкой из
  таблицы, например `[Puppeteer](modules/PUPPETEER_REMOTEOK_STRATEGY.md)`.

Пример уже существующей пары: `TECH_STACK_OVERVIEW.md` ↔ `modules/PUPPETEER_REMOTEOK_STRATEGY.md`
(разбор связки Puppeteer + `remoteOkStrategy.ts`).

## Соглашения по содержимому module-файлов

Ориентир - `modules/PUPPETEER_REMOTEOK_STRATEGY.md`:

1. **Заголовок + обратная ссылка** на `TECH_STACK_OVERVIEW.md` первой строкой
   (`← назад к [макро-обзору стека](../TECH_STACK_OVERVIEW.md)`).
2. **Ссылка "Файл:"** на исходник модуля целиком, кликабельная markdown-ссылка на реальный путь
   в репозитории (не просто текст в бэктиках) - например
   `Файл: [\`apps/api/src/crawler/strategies/remoteOkStrategy.ts\`](../../../apps/api/src/crawler/strategies/remoteOkStrategy.ts)`.
3. **"Зачем именно X"** - короткое объяснение, почему выбрана именно эта технология для этого
   источника/модуля (а не просто "как она работает вообще").
4. **Разбор структуры данных** - если модуль что-то парсит, показать реальный (или приближённый к
   реальному) фрагмент HTML/JSON и таблицу "поле → откуда берётся", со ссылкой на тип/интерфейс в
   коде через `#Lxx` (например
   `[\`RawVacancy\`](../../../apps/api/src/crawler/types.ts#L3)`).
5. **Разделы с кодом** - у каждого такого раздела прямо под заголовком идёт строка-ссылка на
   точное место в исходнике: `→ [\`remoteOkStrategy.ts#L116\`](../../../apps/api/src/crawler/strategies/remoteOkStrategy.ts#L116)`.
Строку `#Lxx` нужно сверять с реальным файлом (`grep -n` перед тем как писать ссылку) - код
   двигается, ссылка должна указывать на актуальное место.
6. **Код-примеры включают нужные `import`** для использованных имён (например `getOrFetch`,
   `waitForSlot`, `cheerio`), даже если в самом исходнике они объявлены в другом месте файла -
   учебный фрагмент должен быть понятен сам по себе, без необходимости искать, откуда что взялось.
7. **Нумерованный построчный разбор кода** после блока кода - что делает каждая ключевая строка/
   вызов, простым языком.

## Ссылки на исходники: технические детали

- Пути - относительные markdown-ссылки от текущего файла до файла в репозитории (например, из
  `.claude/doc/modules/*.md` до `apps/...` это `../../../apps/...`). Не абсолютные пути с диска.
- `#Lxx` - номер строки на момент написания доки. GitHub/VSCode оба понимают этот якорь у
  markdown-ссылки на файл того же репозитория. Это не гарантирует переход "в новом окне" -
  это обычная markdown-ссылка, поведение (новая вкладка/окно) зависит от того, как её открывает
  читатель (например Ctrl/Cmd+клик в VSCode или GitHub).
- Ссылку следует перепроверять (`grep -n` на актуальный код), если менялся сам исходник модуля -
  см. "Поддержание в актуальном состоянии" ниже.

## Поддержание в актуальном состоянии

Как и `.claude/features/`, эти файлы могут расходиться с кодом со временем. Когда меняется код,
который описан в `.claude/doc/` (сигнатуры, номера строк за `#Lxx`, структура парсимых данных),
поправить документацию тем же PR/шагом работы - тот же принцип, что для `CLAUDE.md`/
`README.md`/`ARCHITECTURE.md` в корневом `CLAUDE.md`.

## Когда добавлять новый module-файл

Когда в `TECH_STACK_OVERVIEW.md` появляется технология/связка, которую стоит разобрать подробнее
для презентации (нетривиальный выбор, requires объяснения "почему так", код стоит показать
построчно) - создать `modules/<NAME>.md` по образцу выше и добавить на него ссылку из
соответствующей строки таблицы в `TECH_STACK_OVERVIEW.md`.
