Job-Crawler-Demo: a full-stack pipeline that turns four messy job sites into one searchable index

Not a job board. A demonstration of the plumbing behind one: crawl heterogeneous, sometimes-hostile sites → normalize what they give you → index it for real faceted search — the same shape of problem as any production data-ingestion pipeline.

02 · Pipeline

What actually happens when a source is crawled

01Site 4 job sites, 4 shapes: static HTML, Cloudflare-gated JS, RSS, JSON-LD.
→
02CrawlStrategy Per-source parser. Maps that site's fields into one shape.
→
03RawVacancy The common internal shape — title, company, description, location…
→
04Upsert Dedup by source+id. Applies Elasticsearch's own index mapping.
→
05Search UI Free text, facets, autocomplete, match highlighting.

The two highlighted stages are where "mapping" actually applies — and they mean two different things. Slide 6.

04 · "Did you use mapping?"

Two different questions hiding in one word

ETL mapping

stage 02 — inside each CrawlStrategy

Every source's own vocabulary gets translated into RawVacancy at parse time, per site:

hiringOrganization.name → company

jobLocationType === "TELECOMMUTE" → isRemote

Reconciles four different worlds into one shape, before anything touches the database.

Elasticsearch mapping

stage 04 — the index schema

The literal ES term: field types, keyword vs text sub-fields for facets and autocomplete.

Versioned via CRAWLER_RESULTS_SCHEMA_VERSION — an incompatible change rebuilds the index rather than migrating in place, since it's a derived cache.

This mapping is genuinely defined at upsert time.

So which one was meant? "Mapping data from sources" reads as the ETL sense — which happens earlier, per source, not at the write. Both exist here; the accurate answer names both and says where each one lives.

06 · Why build this

What the demo is actually proving

  • One abstraction, four structurally different sites. The CrawlStrategy interface never changed across static HTML, Cloudflare-gated JS, RSS, and a scoped classifieds site.
  • Real anti-bot problems, real fixes. A live Cloudflare fingerprinting issue forced a mid-build pivot to RSS — documented as it happened, not simulated.
  • A search layer that behaves like production. Faceted filtering, autocomplete, match highlighting, a rebuildable index.
  • Politeness by design. Every source is rate-limited with jitter and cached — a demo scraper is still a scraper.
