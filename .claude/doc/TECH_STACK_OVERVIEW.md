# Стек технологий Job-Crawler-Demo — макро-обзор

## Backend (apps/api)

| Технология | Зачем нужна |
|---|---|
| **TypeScript + Node.js + Express** | Ядро бэкенда и REST API — строгая типизация снижает число runtime-ошибок, Express даёт простой и предсказуемый роутинг |
| **Puppeteer** | Краулинг сайтов, которые рендерят контент через JS (headless-браузер) — нужен там, где сервер отдаёт пустой HTML без JS |
| **Axios + Cheerio** | Быстрый краулинг статических (server-rendered) страниц — не поднимать браузер там, где не нужно, экономия ресурсов |
| **PostgreSQL** | Источник правды для "нефункциональных" сущностей: пользователи, запуски краулов, логи, настройки — реляционные данные с транзакциями |
| **Redis** | Rate limiting (не долбить сайты-источники слишком часто) и хранение состояния текущего запуска краула |
| **Elasticsearch** | Основное хранилище и поисковый движок для собранных вакансий — полнотекстовый поиск, фасеты, релевантность (то, чего Postgres не умеет эффективно) |
| **Coveo-like слой** | Лёгкая обёртка над Elasticsearch, имитирующая enterprise-поиск (фасеты, сортировка по релевантности) — демонстрирует паттерн, используемый в реальных enterprise search-системах |
| **JWT** | Аутентификация пользователей — простой stateless-механизм авторизации для API |
| **Claude API** (сейчас `MockAIEnricher`) | AI-обогащение вакансий: саммари, извлечение навыков, категоризация — демонстрирует интеграцию LLM в pipeline |
| **Winston** | Структурированное логирование — трассировка выполнения краулов и ошибок |

## Frontend (apps/web)

| Технология | Зачем нужна |
|---|---|
| **Next.js + React** | SPA-консоль управления краулером |
| **Feature-Sliced Design (FSD)** | Архитектурная методология для фронтенда — чёткие слои (app→widgets→features→entities→shared), предсказуемые импорты, масштабируемость |
| **shadcn/ui** | Набор UI-компонентов (кнопки, карточки, инпуты) — не изобретать дизайн-систему с нуля |

## Инфраструктура

| Технология | Зачем нужна |
|---|---|
| **Docker + Docker Compose** | Локальное окружение — Postgres, Redis, Elasticsearch поднимаются одной командой, одинаково у всех разработчиков |

## Общая идея стека для доклада

Проект специально показывает **разделение обязанностей между хранилищами**: Postgres — источник правды для операционных данных, Elasticsearch — производный, пересобираемый поисковый индекс, Redis — эфемерное состояние/rate-limiting. А на краулинге — **выбор инструмента под тип сайта** (Cheerio для статики, Puppeteer для JS-рендеринга) — это ключевая архитектурная демонстрация, ради которой проект и задумывался (inspired by enterprise-краулинг вроде SAP).
